## 🎯 План на 26.4.0

### R4. Диагностика без согласия и юридическая модель — ✅ код готов

**Проблема.** Старая модель (AppMetrica: обязательная краш-диагностика +
события по согласию + consent-экран ПДн) юридически уязвима и отклонялась
модерацией RuStore (REQUEST_INSTALL_PACKAGES). Консультация с юристом:
переход на договорную модель — пользовательское соглашение как оферта,
использование приложения как акцепт; диагностика — только opt-in.

- [x] AppMetrica удалена целиком: зависимости (Maven + SPM), движки,
      реестр событий, consent-диалог, тумблер аналитики, ключи хранения (−459 строк)
- [x] Sentry вместо неё: общий фасад `AppDiagnostics` + платформенные движки
      (`sentry-android`, `sentry-cocoa` 9.20.0 — 9.29 не резолвится SPM на Xcode 16.4)
- [x] Opt-in на stable/rc: тумблер в скрытом меню отладки, по умолчанию выключен;
      выключен = SDK не запущен, наружу ноль байт
- [x] Принудительный сбор на dev/beta/contrib (тестовые каналы, тумблер заблокирован)
- [x] Кнопка «Отправить тестовое событие» — проверка канала из приложения
- [x] Пользовательское соглашение (оферта) на gh-pages:
      https://vibe-moments-technologies.github.io/krasava-app/terms.html
- [x] dSYM в CI: `dwarf-with-dsym` + `sentry-cli debug-files upload`
      (секрет `SENTRY_AUTH_TOKEN`, проект `krasava-app`)
- [x] Экран отладки переделан: секции, единые карточки, скролл переживает
      переходы в подменю (реестр `scrollState` в VM)
- [ ] Прогнать тест-событие dev.6 → Sentry и дождаться реального краша
      с символизированным стеком iOS (проверка dSYM-канала)

**DoD:** на stable наружу не уходит ничего без явного включения; тест-событие
видно в Sentry; iOS-краш приходит с читаемым стеком.

## 🧊 Backlog

### B1. Виджеты Android и iOS

**Почему не в 26.3.0:** это две независимые нативные поставки (Glance/`AppWidget`
и WidgetKit + App Group), каждая со своей механикой обновления timeline и
отдельным тестированием на устройстве. Делать «единый KMP-API виджетов» заранее —
преждевременная абстракция.

- [ ] Общий контракт данных в `shared` (ближайшая/текущая пара), без UI
- [ ] **Android first:** Glance-виджет «Сейчас / следующая пара»
- [ ] Обновление виджета после `refreshSchedule` и при смене активного расписания
- [ ] iOS: WidgetKit + App Group container для доступа к данным из extension
- [ ] Таймлайн iOS: перезапуск в моменты `lessonStart` / `lessonEnd`
- [ ] Только после этого — вариант «короткое расписание дня» (2–4 пары)

### B2. Расширение заметок

- [ ] Заметки к преподавателю и к аудитории (нужна ясная семантика:
      преподаватель встречается в разных расписаниях, аудитория — в разных парах)
- [ ] Настройка автоочистки заметок к прошедшим парам (90 дней / семестр),
      **выключена по умолчанию** — тихо удалять пользовательские данные нельзя


### B3. Расширение просмотра расписаний

- [ ] Настройка, которая позволяет пользователю задать количество недель в расписании по умолчанию

### B5. Remote Config — расширение (идея)

Сейчас `config.json` на gh-pages управляет только ссылками соцсетей.
Потенциальные кандидаты на удалённое конфигурирование:

- [ ] Ресурсы университета (ссылки ЛКС, СДО, Пульс, Nextcloud и т.д.)
- [ ] Команда проекта (имена, роли, e-mail, GitHub-логины)
- [ ] Контакты (почта, Issue-ссылка)
- [ ] Текст дисклеймера карт
- [ ] Ссылки на документы (TERMS, PRIVACY, PDP_POLICY)

**Почему не Remote Config RuStore/VK:** это про A/B-тесты и флаги фич.
Для ссылок/контактов — оверкилл + зависимость от чужой инфраструктуры.
Git + gh-pages даёт полный контроль, версионирование и мгновенный деплой.

### B4. Недоиспользованные данные iCal-фида

Фид (`includeMeta=true`) отдаёт больше, чем сейчас парсит `MireaICalParser`.
Маркеры недель уже взяты (источник истины для нумерации, `SemesterWeeks`);
остальное — потенциальные фичи, каждая независима:

- [ ] «N из M недель» в шапке расписания — маркеры недель дают и начало, и конец
      семестра (`X-SV-START`/`X-SV-END` в блоке `X-SCHEDULE-VERSION` — фолбэк границ)
- [ ] Полный тип занятия из `X-META-FULL_LESSON_TYPE` («Практические занятия»
      вместо «ПР») в `LessonDetailScreen`
- [ ] Кнопка «Открыть на карте» в карточке пары: `X-META-AUDITORIUM` несёт
      параметрами `NUMBER=446;CAMPUS=С-20` — надёжнее парсить их, чем `LOCATION`
- [ ] Переход к расписанию преподавателя/аудитории одним тапом из карточки пары:
      в мета-полях уже есть `ID`+`TYPE` (`X-META-TEACHER;ID=707;TYPE=2`)
- [ ] Явный признак «пара раз в две недели»: `RRULE INTERVAL=2` сейчас
      используется только для разворачивания дат
- [ ] Индикация отменённых занятий: `EXDATE` с несколькими датами
      (сейчас просто фильтруется)

### B6. Единый каркас подэкранов

Дубли `SectionCard`/switch-строк по файлам, у каждого экрана свой Scaffold
